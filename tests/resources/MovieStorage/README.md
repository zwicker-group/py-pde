# Backward compatibility resources: MovieStorage

This folder contains `.avi` files (and `.avi.times` files) written by *older* versions
of `py-pde`. The test suite `tests/storage/test_backward_compatibility.py` checks that
the current code can still read them and that the data matches the analytic expectations
defined in `tests/storage/_compat_cases.py`.

## Layout

- `current/`: Files written by the *current* code. This folder is generated by
  `scripts/create_movie_storage_test_resources.py`, is ignored by git, and is **never
  tested**.
- `v<X.Y>/` (e.g., `v1.0/`): Files that were deliberately copied from `current/`. Every
  such folder is tested automatically.
- `legacy_errors/`: Broken files (`empty.avi`, `no_metadata.avi`) used by
  `tests/storage/test_movie_storages.py` to test error handling. Not a version folder.

## Adding files to the test suite

1. Run `python scripts/create_movie_storage_test_resources.py`.
2. Inspect the files in `current/`.
3. Copy the files that should be tested into a new folder named after the `py-pde`
   version, e.g., `v1.0/`, and commit them. Copy the `.avi.times` files, too.

Only copy files when the format is stable. Files in a version folder must never be
regenerated or modified, since they represent the format of that version. Video bytes
may differ between `ffmpeg` versions, so the tests compare decoded data only.
